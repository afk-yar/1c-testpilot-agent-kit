## Проблемы инструмента (не системы)

1. **`tc_table add_rows` не принимает видимые названия колонок**, даже уникальные (`Items`, `Quantity`, `Price`) — отказывает `invalid_column` с текстом «Use a unique column name», хотя колонка одна. Реальный адрес — ПОЛНОЕ ВНУТРЕННЕЕ имя элемента (`ТоварыНоменклатура`, а не `Номенклатура` и не видимый заголовок `Items`). Ни описание действия, ни текст ошибки этого не подсказывают.
2. **`tc_table set_cell_text` тоже требует полное внутреннее имя**, а не «его element name», как сказано в тексте ошибки «column is missing or ambiguous; use its element name» — сообщение вводит в заблуждение: короткое имя (`Номенклатура`) не работает, нужно полное (`ТоварыНоменклатура`).
3. **`tc_field input_text` на ячейке таблицы дает `unsupported_receiver`/`unsupported_element_type`** без явной подсказки, что для таблиц нужен инструмент `tc_table` (set_cell_text/add_rows), а не `tc_field`.
4. **`add_rows` при отказе оставляет частично заполненную строку** (значение не подтверждено, курсор уходит на дальнюю колонку «Actions»), и нет прямого способа откатить/повторить только нужную ячейку — пришлось действовать построчно через `table_add_row`+`set_cell_text`.
5. **`tc_table find_rows` / `choose_row` не поддерживают поиск по колонке таблицы формы выбора справочника** так, как это нужно (колонка есть в `read_rows`, но `find_rows` по ней с другим текстом ищет только среди уже отрисованных строк — по сути бесполезно для несовпадающего текста, сообщение `scope_note` про это предупреждает, но неочевидно до первого прогона).
6. **`get_user_message_texts` иногда отвечает `user_messages_unavailable`** сразу после успешного проведения документа (окно уже сменило заголовок), хотя в этот момент сообщений и не должно быть — стоило бы явно отличать «нет сообщений» от «панель недоступна».
