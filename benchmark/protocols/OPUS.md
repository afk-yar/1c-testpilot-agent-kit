**Проблемы инструмента (не системы):**
1. Отказ ввода в ячейку, закрытую правилом формы (Цена при заданном виде цены), приходит как общий `invalid_element_state` «The element is not in a state that permits this action.» (add_rows, первый set_cell_text) при `readonly: false` у колонки. Причину («To edit the price, clear the price type») удалось получить только через `choose_row` по подсказке, которая появилась лишь на третьем разном отказе (`row_edit_refused`).
2. `find_rows` на форме выбора «Partners (Customers)» вернул `rows_checked: 0, row_count: 0`, хотя `read_rows` на той же таблице секундой раньше вернул 1 строку («Неизвестный партнер»).
3. `delete_row` не подтверждает результат: `deleted: null`, «Command accepted; its effect has not been verified.» — удаление пришлось проверять отдельным read_rows.
4. Поле выбора из списка (ТоварыВариантОбеспечения) в ячейке таблицы: `set_cell_text` → `unsupported_element_type`, `select_option` → `target_hidden` (колонка вне режима редактирования). Сработала только цепочка activate + change_row + `execute_choice_from_choice_list`; при этом на строке 1 ответ был `value_after: null, changed: null`, а фактически открылся модальный «Select action» — факт окна в ответе действия не отражен, увидел только через get_active_window.
5. `input_text` несуществующего значения ссылочного поля оставляет открытым выпадающий список с 0 элементов (`get_choice_list` → `items[0]`, `status: unknown`), текст в поле без значения; явного признака «значение не найдено» нет.
6. `get_user_message_texts` в карточке документа после успешного проведения возвращает `user_messages_unavailable` (ok: false) — отличить «сообщений нет» от «панель недоступна» нельзя.
