# Методика бенчмарка

Как прогнать сценарий на своем агенте или модели и получить результат, сравнимый с
[`results.md`](results.md).

## Состав

| Что | Где |
|---|---|
| Сценарий, 12 шагов с шестью ловушками | [`scenario.md`](scenario.md) |
| Грабли инструмента, которые агент читает перед стартом | [`../skill/testpilot-1c/SKILL.md`](../skill/testpilot-1c/SKILL.md) |
| Протоколы прошлых прогонов | [`protocols/`](protocols/) |
| Подсчет токенов и стоимости | [`../scripts/`](../scripts/) |

## 1. База и тест-клиент

База — 1С:ERP 2.5.27 с английским интерфейсом (прогоны шли на 2.5.27.79, платформа 8.3.27).
Ловушки сценария завязаны на поведение этой конфигурации: на другой версии ERP часть из них может
вести себя иначе.

Тест-клиенты поднимает сам агент через профили testpilot (`profiles.yaml` сервера). Один прогон —
один профиль со своим портом; параллельные прогоны — на разных профилях. Профили в протоколах
называются `stend`, `stend-2`, `stend-3` (порты 1545, 1546, 1547).

Перед стартом порт профиля должен быть свободен. Проверять по процессам, а не через `tc_session`
list_connections: тот видит только клиентов своего MCP-сервера, а у агента под тестом сервер свой.
На Windows: пустой `netstat -ano | Select-String ':1545\s'` — порт свободен; занят — найти
`1cv8c.exe` с `-TPort 1545` в командной строке и завершить по PID.

Для сверки результата нужен доступ к данным базы запросом: любой MCP к 1С с выполнением запросов,
консоль запросов или конфигуратор. Агенту под тестом этот доступ не давать.

### Предусловия

В базе должны быть тестовые объекты. Запрос должен вернуть все восемь строк; не хватает строки —
сценарий не пройдет.

```
ВЫБРАТЬ "Партнер" КАК Вид, Партнеры.Наименование КАК Имя ИЗ Справочник.Партнеры КАК Партнеры ГДЕ Партнеры.Наименование = "Тест Клиент"
ОБЪЕДИНИТЬ ВСЕ ВЫБРАТЬ "Контрагент", Контрагенты.Наименование ИЗ Справочник.Контрагенты КАК Контрагенты ГДЕ Контрагенты.Наименование = "Тест Клиент (контрагент)"
ОБЪЕДИНИТЬ ВСЕ ВЫБРАТЬ "Соглашение", Соглашения.Наименование ИЗ Справочник.СоглашенияСКлиентами КАК Соглашения ГДЕ Соглашения.Наименование = "Тест Соглашение с клиентом"
ОБЪЕДИНИТЬ ВСЕ ВЫБРАТЬ "Номенклатура", Номенклатура.Наименование ИЗ Справочник.Номенклатура КАК Номенклатура ГДЕ Номенклатура.Наименование В ("Тест Товар 1", "Тест Товар 2")
ОБЪЕДИНИТЬ ВСЕ ВЫБРАТЬ "Организация", Организации.Наименование ИЗ Справочник.Организации КАК Организации ГДЕ Организации.Наименование = "Тест Организация"
ОБЪЕДИНИТЬ ВСЕ ВЫБРАТЬ "Склад", Склады.Наименование ИЗ Справочник.Склады КАК Склады ГДЕ Склады.Наименование = "Тест Склад основной"
ОБЪЕДИНИТЬ ВСЕ ВЫБРАТЬ "Вид цены", ВидыЦен.Наименование ИЗ Справочник.ВидыЦен КАК ВидыЦен ГДЕ ВидыЦен.Наименование = "Тест Цена продажи"
```

Что должно быть у объектов: партнер-клиент «Тест Клиент» с контрагентом «Тест Клиент (контрагент)»;
соглашение с ним в USD с видом цены «Тест Цена продажи»; организация и склад, которые
подставляются в заказ из соглашения; два штучных товара с НДС 20 %. Цен номенклатуры в базе нет —
это часть ловушки. Скрипта заведения данных в наборе пока нет.

Эталон оплаты зависит от автосуммы в рублях, которую база подставляет за 1 700 USD. Во всех
наших прогонах она была 143 885,45 ₽, отсюда 84 638,50 ₽ за 1 000 USD. В вашей базе курс будет
другим: эталон считается как `1000 × автосумма / 1700`, до копеек, автосумма — из протокола шага 9.1.

## 2. Метка прогона

Метка `<T>` — короткий латинский код агента и модели: `OPUS`, `S55H`, `CX6M`. Она попадает в
комментарии документов (`HARD-<T>`), по ней потом ищется все созданное, и в имя протокола. Метка не
должна повторять уже использованную в этой базе.

## 3. Промпт

Одинаковый для всех прогонов, меняются только пути, профиль, метка и файл протокола.

### Субагент Claude Code

Запуск фоном; модель и effort фиксируются определением агента (файл в `~/.claude/agents/` с полями
`model` и `effort` во frontmatter и телом «Выполняй задачу из промпта сам»).

```
Ты UI-тестировщик 1С. Выполни сценарий `<путь>/benchmark/scenario.md` целиком, по шагам.
Скилл testpilot-1c из сценария лежит в `<путь>/skill/testpilot-1c/SKILL.md`, прочитай его перед стартом.

Твои параметры:
- профиль testpilot: `<профиль>` (порт <порт>)
- метка `<T>` = `<метка>`
- файл протокола: `<папка протоколов>/<метка>.md` (создай через Write, дополняй через Edit)

Схемы инструментов testpilot отложенные: загрузи через ToolSearch запросом `select:mcp__1c-testpilot__tc_session,mcp__1c-testpilot__tc_find,mcp__1c-testpilot__tc_window,mcp__1c-testpilot__tc_field,mcp__1c-testpilot__tc_table,mcp__1c-testpilot__tc_form,mcp__1c-testpilot__tc_app`.

НЕ вызывай субагентов (Agent/Task/Workflow) — выполняй задачу сам. Не пользуйся другими MCP к базе — только testpilot. Не правь никакие файлы, кроме своего протокола.

Финальным сообщением верни строку итогов из протокола и список проблем инструмента.
```

### Любой другой агент (так шел Codex)

```
Ты UI-тестировщик 1С. Выполни сценарий <путь>/benchmark/scenario.md целиком, по шагам. Скилл testpilot-1c из сценария лежит в <путь>/skill/testpilot-1c/SKILL.md, прочитай его перед стартом. Твои параметры: профиль testpilot <профиль> (порт <порт>); метка <T> = <метка>; файл протокола <папка протоколов>/<метка>.md (создай и дополняй по ходу). Инструменты testpilot - MCP-сервер 1c-testpilot. НЕ запускай субагентов, выполняй задачу сам. Не пользуйся другими MCP к базе - только testpilot. Не правь никакие файлы, кроме своего протокола. Финальным сообщением верни строку итогов из протокола и список проблем инструмента.
```

Что нужно агенту, кроме промпта:
- подключенный MCP-сервер 1c-testpilot (как подключить — README автора);
- право писать файл протокола без подтверждений;
- чистый сеанс: прогон не должен видеть прошлые протоколы, результаты и этот файл.

### Codex CLI: что мешало запуску

Проверено на Codex CLI 0.159 под Windows, запуск из мультиплексора
[herdr](https://herdr.dev) через `herdr agent start`/`agent prompt`.
- Флаги: `--dangerously-bypass-approvals-and-sandbox -m <модель> -c model_reasoning_effort=<уровень>`.
  В режиме `--sandbox workspace-write` запись файла зависала больше 11 с и обрывалась.
- Промпт отправлять только после окончания старта MCP-серверов: ранний промпт прерывает их запуск.
- После отправки проверить, что агент перешел в работу: длинный текст иногда остается в поле ввода,
  нужен отдельный Enter.

## 4. Сверка с базой

После прогона — один запрос по метке. Параметры: `Метка` = `HARD-<T>`, `МеткаОплаты` = `HARD-<T> оплата`.

```
ВЫБРАТЬ Заказ.Ссылка КАК Ссылка ПОМЕСТИТЬ Заказы ИЗ Документ.ЗаказКлиента КАК Заказ ГДЕ Заказ.Комментарий ПОДОБНО &Метка;
ВЫБРАТЬ "Заказ" КАК Документ, Заказ.Номер КАК Номер, Заказ.Проведен КАК Проведен, NULL КАК Количество, NULL КАК Цена, Заказ.СуммаДокумента КАК Сумма, NULL КАК СуммаНДС, Заказ.Валюта.Наименование КАК Валюта, Заказ.Партнер.Наименование КАК Деталь, ВЫРАЗИТЬ(Заказ.Комментарий КАК СТРОКА(100)) КАК Комментарий
ИЗ Документ.ЗаказКлиента КАК Заказ ВНУТРЕННЕЕ СОЕДИНЕНИЕ Заказы КАК Заказы ПО Заказ.Ссылка = Заказы.Ссылка
ОБЪЕДИНИТЬ ВСЕ ВЫБРАТЬ "Строка заказа", Товары.НомерСтроки, ИСТИНА, Товары.Количество, Товары.Цена, Товары.Сумма, Товары.СуммаНДС, "", Товары.Номенклатура.Наименование, ПРЕДСТАВЛЕНИЕ(Товары.ВариантОбеспечения)
ИЗ Документ.ЗаказКлиента.Товары КАК Товары ВНУТРЕННЕЕ СОЕДИНЕНИЕ Заказы КАК Заказы ПО Товары.Ссылка = Заказы.Ссылка
ОБЪЕДИНИТЬ ВСЕ ВЫБРАТЬ "Счет", Счет.Номер, Счет.Проведен, NULL, NULL, Счет.СуммаДокумента, NULL, Счет.Валюта.Наименование, "", ""
ИЗ Документ.СчетНаОплатуКлиенту КАК Счет ВНУТРЕННЕЕ СОЕДИНЕНИЕ Заказы КАК Заказы ПО Счет.ДокументОснование = Заказы.Ссылка
ОБЪЕДИНИТЬ ВСЕ ВЫБРАТЬ РАЗЛИЧНЫЕ "Накладная", Накладная.Ссылка.Номер, Накладная.Ссылка.Проведен, NULL, NULL, Накладная.Ссылка.СуммаДокумента, NULL, "", "", ""
ИЗ Документ.РеализацияТоваровУслуг.Товары КАК Накладная ВНУТРЕННЕЕ СОЕДИНЕНИЕ Заказы КАК Заказы ПО Накладная.ЗаказКлиента = Заказы.Ссылка
ОБЪЕДИНИТЬ ВСЕ ВЫБРАТЬ "Оплата", Оплата.Номер, Оплата.Проведен, NULL, NULL, Оплата.СуммаДокумента, NULL, Оплата.Валюта.Наименование, Оплата.НомерВходящегоДокумента, ВЫРАЗИТЬ(Оплата.Комментарий КАК СТРОКА(100))
ИЗ Документ.ПоступлениеБезналичныхДенежныхСредств КАК Оплата ГДЕ Оплата.Комментарий ПОДОБНО &МеткаОплаты
ОБЪЕДИНИТЬ ВСЕ ВЫБРАТЬ "Взаиморасчеты оплаты", Расшифровка.Ссылка.Номер, ИСТИНА, NULL, NULL, Расшифровка.СуммаВзаиморасчетов, NULL, Расшифровка.ВалютаВзаиморасчетов.Наименование, "", ""
```

## 5. Оценка: 16 точек

Да — 1, частично — 0,5, нет — 0. Частично: точка взята со второй попытки, обходом, который увел в
сторону, или «прошел» стоит рядом с честно записанным расхождением. Источник — протокол (П) или
запрос сверки (Б); при расхождении верна база.

| № | Точка | Шаг | Что считается «да» | Источник |
|---|---|---|---|---|
| 1 | Отказ прямого входа записан дословно | 1 | «You can enter the document only based on another document or a contract with a customer.» | П |
| 2 | Ответ на несуществующего партнера записан | 2.1 | ввод не принят (`committed: false` / pending), что осталось в поле | П |
| 3 | Пустая форма выбора распознана, клиент введен обходом | 2.2 | записано, что форма не показывает «Тест Клиент»; клиент заполнен иначе (goto_row + choose_row или ввод текстом) | П |
| 4 | Клиент в правильном поле с первого раза | 2.2 | не было попытки заполнить поле контрагента вместо клиента | П, Б: партнер = Тест Клиент |
| 5 | Ловушка «вид цены» обойдена | 3 | все три цены 100, 250, 77 введены после очистки вида цены. Отказы до того, как причина найдена, — норма. Частично: какая-то цена не встала или агент ушел вводить суммы в другие колонки | П |
| 6 | Ошибка проведения записана, строки исправлены, суммы сверены | 4 | «Column "Quantity" in line 3 of the "Goods" list is not filled in»; строк 2; 1 200 / 200 и 500 / 83,33 | П, Б |
| 7 | Заказ проведен, номер получен | 5 | номер в протоколе = номеру в базе, проведен | Б |
| 8 | Снимок формы сравнен после проведения | 5 | список изменений из compare_snapshot: номер, дата, дата согласования, видимость гиперссылок | П |
| 9 | Отказ от сохранения проверен переоткрытием | 6 | комментарий в базе `HARD-<T>`, не `ИЗМЕНЕНО` | П, Б |
| 10 | Накладная: две попытки и остановка | 7 | дважды «To start shipment, make sure the "Ship" action is specified...»; в строках Ship; накладной нет | П, Б |
| 11 | Счет на 1 700 создан и открыт | 8 | счет на основании заказа, 1 700 USD, проведен | П, Б |
| 12 | Три сообщения при нулевой оплате | 9.2 | «Document amount», «Incoming document date», «Reference number» — не заполнены | П |
| 13 | Оплата 1 000 USD пересчитана верно | 9.3 | сумма и взаиморасчеты в базе совпали с эталоном | Б |
| 14 | Обратный путь: к оплате 700, оплачивается 1 000 | 10 | цифры из таблицы этапов после Refresh | П |
| 15 | Итог в списке: 59 % оплаты | 11 | «Amount paid (%)» = 59 для своего заказа | П |
| 16 | Протокол без ложных «прошел» | все | каждый «прошел» подтвержден фактом; расхождения с базой не выданы за успех | П против Б |

## 6. Стоимость

- Claude Code: `SUBAGENTS_DIR=<папка subagents сессии> python scripts/usage_claude.py <agentId>`.
  Цены в скрипте — на сентябрь 2026, сверить со страницей Anthropic.
- Codex CLI: `python scripts/usage_codex.py ~/.codex/sessions/<ГГГГ>/<ММ>/<ДД>/rollout-*.jsonl`.
  Журнал не показывает запись в кеш: новый вход считать по цене входа.
- Другой агент: свой разбор журнала. Нужны новый вход, запись в кеш, чтение кеша, выход, число
  ходов и вызовов, время от первого вызова до финального сообщения.

Цены брать с официальной страницы поставщика на дату прогона и записывать вместе с источником.
Главная статья расходов — повторное чтение контекста из кеша на каждом ходе: у Claude 73–83 % цены.

## 7. Как добавить свой результат

1. Протокол — в `protocols/<метка>.md`.
2. В `results.md` — строка в таблицу и абзац: агент и его версия, модель, effort, баллы, время,
   стоимость, особенности прогона. Отметить версию скилла и testpilot: правка скилла меняет условия.
3. В `report.html` — объект в массиве `M` и столбец в `CHECKS` (16 значений `y`/`p`/`n` по порядку
   точек); цвет — новая переменная `--s<N>` в обеих темах. Проверить пределы осей в вызовах `hbars`.

Один прогон на модель устойчивость не доказывает. Для вывода о модели — минимум три прогона с
разными метками.
